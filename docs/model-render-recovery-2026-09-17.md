# 이름표만 표시되는 모델과 그래픽 연결 복구

## 발견한 경로와 수정

- 필드는 정규화된 모델 객체가 생긴 시점에 준비 완료를 보고했다. GPU에 실제 메시가 제출되기 전이므로 로딩 성공과 화면 표시 성공이 달랐다. 이제 메시의 첫 `onAfterRender`를 확인한 뒤 이동·전투를 허용한다.
- 로딩·실패 상태에서는 개체 이름표와 공격 효과를 표시하지 않는다. 원격 플레이어의 위치 보간도 모델 준비 전에 진행하지 않는다. 로딩/실패 안내 표식은 포켓몬 모델로 세지 않는다.
- 필드의 거리·시야·개체 수 제한은 유지하되 정규화한 캐릭터의 메시별 frustum culling은 끈다. 원본 스킨의 바인드 포즈 경계가 애니메이션과 달라 몸체만 제외될 수 있는 경로를 없앴다. 이전 개별 모델 화면은 이미 같은 방식이었다.
- 비어 있는 메시·숨긴 몸체·전체 투명 재질·빈 draw range는 준비 단계에서 거부한다. 첫 렌더가 45초 동안 끝나지 않으면 실패/재시도를 제공한다. 인스턴스의 정규화 실패가 전체 필드를 제거하지 않게 막고, 공유 캐시 자원은 R3F 자동 폐기 대상에서 제외했다.
- Three의 WebGPU/WebGL 장치 손실은 원래 렌더러 내부 플래그만 바꾸며 게임 시뮬레이션을 정지시키지 않았다. 이제 준비 판정을 전부 무효화하고 탐험을 일시 정지하며 기존 캔버스를 해제한다. `3D 화면 다시 시작`으로 새 렌더러를 만들고 실제 몸체가 다시 그려진 뒤 `계속 탐험`으로 재개한다. 포켓몬·진행·대기 중인 서버 요청은 버리지 않는다.

## 검증과 한계

- 모델 정규화·캐시·LOD·월드 이동 게이트·렌더 스냅샷 관련 Vitest 28개 통과.
- 브라우저에서 실제 GLB 요청 실패, 지연, 정상 GLB의 재질만 전체 투명으로 바꾼 응답을 각각 재현했다. 준비 완료/이름표/이동을 차단하고 정상 GLB 재시도로 복구하는 것을 확인했다.
- 화면 전환 2회와 데스크톱→모바일→데스크톱 전환 후 실제 메시 그리기 횟수가 증가하고, 그려지지 않은 개체에 이름표가 붙지 않는 것을 확인했다. 캡처에서 몸체도 확인했다.
- `WEBGL_lose_context` 확장으로 실제 그래픽 컨텍스트를 잃게 하고 일시 정지·렌더러 재생성·재개를 확인했다. WebGPU 장치 손실은 같은 콜백에 연결했지만 실제 하드웨어 장치 손실까지 재현한 것은 아니다.
- 카운터는 메시 제출 근거이지 모든 픽셀의 가시성이나 전 종의 외형 품질 보증이 아니다. 사용자가 본 정확한 종·지역은 아직 확인되지 않았으며 모든 모델의 개별 시각 검토가 완료된 것은 아니다.

브라우저 산출물: `artifacts/model-draw-readiness-v2`, `artifacts/recovery-final`. 배포 확인은 GitHub Actions와 운영 `/version.json`을 기준으로 한다.
