# 성도에서 관동으로 이어지는 모험

2026-09-14 변경. `src/game/campaign.ts`가 진행·레벨 규칙, `src/game/growth.ts`가 합치기 보상을 정의한다. 아래 수치와 트레이너 팀은 이 게임의 설계이며 원작 카트리지의 팀·레벨을 그대로 재현한 자료가 아니다. 종·기술·성장곡선 출처는 [pokemon-sources.md](pokemon-sources.md), 성도 출현표와 지도 연결 근거는 [world-map-sources.md](world-map-sources.md)에 있다.

## 성장

- 합치기 경험치: `floor(보내는 개체의 누적 XP × 0.2 + 종 기본 경험치 × 레벨 ÷ 7 × 5 × 희귀도 배수)`.
- 희귀도 배수: `clamp(sqrt(10 / max(0.1, 출현지수)), 1, 4)`. 출현지수가 낮을수록 높다. 관동은 현재 맵의 지역별 종 슬롯을 균등하게 계산하고, 성도는 골드 낮 시간의 걷기/수영 슬롯 가중치를 사용한다. 지역을 동일한 비중으로 평균낸 게임용 지수이며, 사용자가 실제로 만난 횟수가 아니다. 출현표가 없는 종도 배수 상한은 4다.
- 이미 합친 누적 XP 전체에 희귀도 배수를 다시 곱하지 않아 중복 합치기로 경험치를 계속 배증시키지 않는다. 레벨 100 상한·초과 XP를 확인창에서 미리 보여준다. 남길 개체를 사용자가 고르며, 보내는 개체의 신경 회로와 학습 기록은 합치지 않는다.
- 출전 개체는 승리 XP 100%, 살아 있는 대기 팀원은 각 80%, 출전 개체보다 레벨이 낮은 팀원은 각 100%를 받는다. 기절한 개체와 박스 개체는 받지 않는다. 공유 설정을 끄면 출전 개체만 받는다.

## 진행과 레벨

| 단계 | 도전 레벨 | 다음 조건 |
| --- | --- | --- |
| 성도 스타터 | Lv.5 치코리타·브케인·리아코 | 연두마을, 골드 수집 기록으로 시작 |
| 성도 체육관 8곳 | 10, 16, 21, 26, 30, 34, 38, 42 | 도라지→고동→금빛→인주→진청→담청→황토→검은먹 |
| 성도 리그 | 42–50 | 동성폭포에서 일목→독수→시바→카렌→목호 |
| 관동 체육관 8곳 | 54, 56, 58, 60, 62, 64, 66, 68 | 성도 챔피언을 이기면 지도에서 관동 이동 가능 |
| 관동 리그 | 70–78 | 석영고원에서 칸나→시바→국화→목호→그린 |
| 레드 | 82–88 | 두 지역 배지 16개와 양 리그 클리어 후 은빛산 |

리그는 트레이너 한 명을 이길 때마다 진행을 저장한다. 트레이너 사이에 회복·정비할 수 있고, 패배하면 현재 트레이너부터 재도전한다. 전투 도중 저장도 같은 상대와 턴으로 복원한다. 양 리그 클리어 뒤 은빛산 야생 레벨은 72–80이다. 그 외 성도 도로는 체육관 단계에 맞춘 고정 레벨 구간, 새 모험의 관동은 후반 레벨 구간을 사용한다. 선두 레벨에 따라 야생 레벨을 올리지 않는다.

관동은 기존 레드 위치별 종 목록, 성도는 고정 골드 위치별 종·가중치를 유지한다. 버전 선택은 수집 기록만 바꾼다. 성도 스폰은 골드 가중치를 직접 사용한다. 새 레벨 구간은 새로 생기는 야생 개체에 적용하고 저장돼 있던 개체의 레벨·기억을 강제로 바꾸지 않는다.

기존 관동 저장은 시작 위치·배지·팀·박스·도감·여행 권한과 초반 관동 레벨을 보존한다. 새 `campaign` 진행에는 성도 배지와 각 리그 진척을 별도로 저장한다. 기존 `player.badges`, `defeatedGyms`, `championDefeated`는 관동 기록으로 유지하며, 이미 챔피언을 이긴 옛 저장은 관동 리그 완료로 복원한다.

## 상점·박스·지도

몬스터볼만 판매·표시·사용한다. 기존 슈퍼볼·하이퍼볼은 수량을 1:1로 몬스터볼에 더하고 호환용 옛 키를 0으로 저장한다. 가격은 20원, 활동 30초마다 무료 1개 보충(20개까지)이다. 승리 후 포획은 몬스터볼 1개로 확정된다.

전투 중에도 구매할 수 있다. 탐험 패널의 팀·박스 관리 창을 열면 진행과 서버 응답을 정리한 뒤 대기 포켓몬을 맡기거나 데려온다. 현재 출전 중인 개체, 마지막 팀 개체, 마지막 생존 개체는 맡기지 못한다. 현재 HP·PP와 회로 기록을 유지하고 대기 중인 교체 명령은 취소한다. 무료 회복과 진화·합치기는 전투 종료 후 이용한다.

마을의 평평한 포장과 실제 렌더 지형 삼각형의 높이를 맞추고 외곽을 부드럽게 연결했다. 건물 충돌과 기존 이동 좌표는 유지한다. 은빛산은 동성폭포에서 연결되는 실제 지형이며 지도에서 다음 도전 목적지를 확인할 수 있다.

## 검증 범위

통합 변경 후 `pnpm exec vitest run --maxWorkers=2`는 36개 파일·204개 검사를, Linux musl 릴리스의 `cargo test`는 21개 검사를 통과했다. `pnpm run build`도 통과했다. 기존 대형 JavaScript 청크 경고는 남아 있다.

`tests/campaign-progression.test.ts`는 두 지역 체육관 16전, 사천왕·챔피언 10전, 레드전을 실제 엔진 턴으로 진행하고 리그 저장에서 재실행한 결과의 일치를 검사한다. 검증용 Lv.100 팀을 사용하므로 일반 플레이의 성장 시간이나 난이도가 최적이라는 증거는 아니다. 별도로 공유 비율, 희귀도·레벨 보상, 전투 중 박스 인덱스 보존, 구 저장 변환과 잘못된 진행 거부를 검사한다.

브라우저 흐름 검사는 `tests/ui/campaign-progression.spec.ts`, 기존 합치기·체육관·관동 시나리오에 있다. 흐름 검사의 모델 요청 차단 및 서버 응답 대역은 UI 검증용이며 실제 제공자 실행 증거로 세지 않는다. 실제 모델 로딩은 기존 `world-regions.spec.ts`와 분리해 확인한다. 서버 저장 검증은 `rust-server/src/save_validation.rs`의 대응 테스트로 확인한다.

## 로컬 실행

별도 터미널에서 각각 실행한다. 프론트엔드는 백그라운드로 실행하지 않는다.

```powershell
.\scripts\start-rust-server.ps1 -AppOrigin 'http://127.0.0.1:5186,http://localhost:5186'
pnpm dev --port 5186 --strictPort
```

접속 주소는 `http://127.0.0.1:5186`이다. API는 8080, 기존 로컬 개발 PostgreSQL은 55432를 사용한다. 다른 프론트엔드 포트를 쓰면 `AppOrigin`에도 같은 주소를 지정한다.
