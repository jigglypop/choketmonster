# 성도 모델 리깅과 동작

## 종별 보정과 단계 검토

공통 체형만으로 부위를 구분할 수 없는 모델은 원본 연결요소의 정규화 위치를 기준으로 종별 프로필을 적용한다. 레디바(165)는 좌우 각각 세 개의 팔다리 체인과 붉은 딱지날개·흰 뒷날개 체인을 따로 둔다. 원본에서 확인한 팔다리 세 쌍과 날개 두 쌍을 각각 움직이므로, 단순한 좌우 한 쌍 관절로 전체 표면을 함께 당기지 않는다. 초라기(170)는 몸통과 분리된 좌우 더듬이 연결요소에 각각 네 관절 체인을 배치한다. 누오(195)는 원본의 두 발 연결요소를 발 관절에 고정하고 몸통에서 다리 가중치를 제거했다. 팔은 몸통과 이어진 어깨 기하가 벌어지지 않는 작은 진폭으로 제한한다.

`scripts/review-johto-rigging.ts "165,170,195"`처럼 쉼표로 구분한 종 번호를 넘기면 선택한 원본 GLB를 현재 코드로 리깅하고, `artifacts/johto-rig-review/<번호>-phases.png`에 원본·대기·걷기·공격의 0, 0.25, 0.5, 0.75 단계를 저장한다. 브라우저 검사는 `scripts/johto-rig-review-probe.ts`에서 실행되며 다음 항목을 함께 기록한다.

- 원본과 준비 후 동작 클립 서명 및 원본 클립 보존 여부
- 동일 템플릿에서 만든 두 복제본의 본·스켈레톤 비공유와 한 복제본만 움직였을 때의 독립성
- 동일 좌표 정점을 용접한 삼각형 연결요소별 소재, 정점 수, 정규화 중심과 크기
- 걷기·공격 단계에서 삼각형 모서리가 바인드 자세보다 늘어난 비율과 해당 정점의 본 가중치

누오에는 현재 검토된 결과의 회귀 감시값으로 최대 상대 모서리 늘어남 `2.5`를 적용한다. 이 수치 검사는 비정상적으로 큰 찢어짐을 찾는 자동 게이트다. `automatedChecksPassed`는 유한한 경계, 복제 독립성, 클립 조건과 이 변형률 한도가 통과했다는 뜻이며 시각 검수 통과를 뜻하지 않는다. 보고서는 항상 `visualReview: requires-human-inspection`을 남긴다. 단계 이미지는 얼굴·몸통의 구멍, 교차, 날개·다리·더듬이의 잘못된 대응을 사람이 직접 확인해야 한다.

원본 리깅 유무를 이유로 성도 출현 종을 제외하지 않는다. 확보한 152~251번 모델 100종을 대상으로 부족한 관절과 동작을 직접 추가한다. 골드의 야생 출현 원본은 그대로 보존한다.

## 원본과 작업본

원본은 `Pokemon-3D-api/assets` 커밋 `429de1288cea0d43f5b4f56305d2276e94239d65`의 GLB다. 로컬 원본 100개, 총 36,949,820바이트를 파일 크기·Git blob SHA-1·기존 검사 manifest의 SHA-256과 대조했다. `data/local/pokemon-models-expanded/<commit>/`의 원본은 수정하지 않는다.

원본 9종은 골격과 애니메이션을 함께 제공하므로 그대로 사용한다. 나머지 91종에는 자체 대기·이동·공격·피격 동작을 추가한다. 54종의 정적 메시에는 새 골격과 정점별 스킨 가중치를 만들고, 코산호(222)는 원본이 허리 하나에만 실질적으로 연결돼 있어 다관절 스킨을 새로 만든다. 나머지 36종은 기존 골격·가중치를 이용한다. 원본 상태 분류는 `docs/pokemon-rigging-metadata.json`에 유지하며 화면은 자체 제작 동작임을 표시한다.

## 실행 방식

`src/three/johto-rig.ts`는 몸 형태와 실제 모델 크기에 맞춰 관절을 배치한다. 정적 메시의 노드 변환을 동일한 좌표계로 옮기고 부위별로 최대 네 관절에 가중치를 부여한다. 원래 표면·UV·재질은 유지한다. 이미 골격이 있는 모델은 관절의 원래 회전과 축을 기준으로 동작을 추가한다. 시뮬레이션 난수와 개체의 뇌 상태는 사용하지 않는다.

모델 로더는 다운로드한 템플릿에 한 번 리깅을 적용한다. 게임의 기존 SkeletonUtils 복제 경로로 개체마다 별도의 골격을 만든다. 동작 클립은 `CM_idle`, `CM_walk`, `CM_attack`, `CM_damage`이며 게임의 행동 전환에서 선택한다. 이것은 해당 게임을 위해 제작한 기본 동작이며 원작 애니메이션이나 모든 기술별 전용 연출을 복원한 것이 아니다.

치코리타의 원본 바인드 자세는 덩굴 두 줄이 완전히 펼쳐져 있다. 일반 동작에서는 `LFeeler01`·`RFeeler01` 이하의 체인을 접어 캐릭터 표시 크기를 정상화한다. 덩굴·본체 메시를 삭제하지 않으며 바인드 자세 자체도 바꾸지 않는다.

## 검증과 로컬 산출물

- `scripts/inspect-johto-rigging-source.py`: Blender로 원본 메시·골격·좌표·가중치 검사. Blender가 표시용으로 만드는 Icosphere는 원본 GLB 기하가 아니다.
- `scripts/verify-johto-rigging.ts --export`: 실제 원본 GLB의 WebGL 디코딩, 바인드 자세 오차, 미연결 정점·가중치 합, 네 동작의 정점 변형과 과도한 확장 검사. 로컬 작업본 GLB와 렌더를 출력한다.
- `artifacts/johto-rigging/verification.json`: 종별 원본 SHA-256, 검사 수치와 통과 여부.
- `artifacts/johto-rigging/<번호>.glb`: 자체 동작을 추가한 91종 작업본. 원본 동작을 그대로 쓰는 9종은 중복 내보내지 않는다.

생성 모델의 숫자 검사와 실제 장면 시각 검토를 구분한다. 자동 가중치는 모든 자세에서 미술 품질을 보증하지 않으며, 현재 검증한 네 기본 동작 밖의 과장된 자세나 새로운 기술에는 추가 조정이 필요하다.

## 배포 경계

모델 원본의 권리와 출처는 기존 [모델 출처](pokemon-models.md) 정책을 따른다. 로컬 작업본 GLB를 공개 S3나 Git에 올리지 않는다. 배포에는 자체 제작한 리깅 코드만 포함하며 브라우저가 기존 고정 원본 URL에서 받은 모델에 적용한다. 원본 모델·텍스처·게임 추출 애니메이션을 새로 재배포하는 허가를 얻었다고 해석하지 않는다.
