# 모델 로딩과 수동 조작 수정

## 원인과 변경

- 필드의 16개 캐시와 팀·도감의 10개 캐시가 서로 별도였다. URL별 진행 중 요청과 파싱된 GLTF를 공유하는 24개 캐시로 합쳤다. 활성 뷰의 참조가 남은 자산은 지우지 않으며, 해제된 자산부터 오래된 순서로 정리한다. 모델별 스켈레톤·애니메이션 상태는 계속 별도로 소유한다.
- 모델 clone을 만들 때마다 최대 25개 자세의 전체 정점을 다시 계산했다. 원본 캐시마다 크기·원점·접지 후보 정점을 한 번 준비하고 clone이 공유하도록 했다. 최초 준비는 자세 사이에 이벤트 루프로 제어를 돌려줘 입력 처리가 끊기지 않게 한다. 같은 모델 재표시는 다운로드·파싱·자세 계산을 반복하지 않는다.
- 매 프레임 접지 계산은 자세별 하단 6% 높이 안의 정점들을 합친 후보 집합을 사용한다. 기절처럼 모델이 옆으로 기울면 전체 정점 계산으로 돌아간다. 캐시 정리 시 재질·기하·텍스처를 중복 해제하지 않고 ImageBitmap도 닫으며, 개체 제거 시 별도 스켈레톤을 해제한다.
- 장소 설명은 지역·장소·배지·분포 조건이 바뀔 때만 다시 계산한다. 단순 문구는 바뀐 경우에만 textContent로 갱신한다. 출입구 DOM 라벨은 14m 이내에만 만들며 출입구 링과 클릭 범위는 유지한다.
- 전투 시작·종료·포획 선택은 음악 cue를 바꾸지 않는다. 주변 지역 음악과 재생 위치를 유지한다.
- 박스 진화는 전투 전체 상태가 아니라 해당 개체의 전투 참가 여부로 제한한다. 레벨·도구 조건과 개체 ID·뇌·IV·특성을 보존한다. 새 팀 개체를 생성하는 껍질몬 분기는 전투 종료 후 가능하다.
- 마을에서 키 입력이나 클릭 이동을 마치면 수동을 유지한다. 명시적인 자동 선택은 가능하며, 마을 밖에서는 목적지 도착 후 자동으로 돌아간다. 관련 AGENTS.md 규칙도 수정했다.

## 확인

- 관련 단위 검사 29개 통과, TypeScript와 프로덕션 빌드 통과.
- 실제 모델 1·130·152·208·445·727번으로 동시 요청의 자산 동일성, 캐시 재방문, 독립 clone과 idle/walk/attack 접지를 검사했다. 샘플 프레임의 기존 전체 정점 결과와 최대 높이 차이는 0.000000007m 미만이었다.
- 동일한 130·152·445번의 clone 준비 시간은 기존 약 10–18ms에서 약 0.2–0.7ms였다. 재방문 캐시 대기는 0–0.1ms였다. 브라우저 CPU 작업 측정이며, 전체 게임 FPS나 최초 네트워크 다운로드 속도 개선 수치는 아니다.
- 배틀 음악 연속 재생, 박스 진화와 전투 참가자 보호, 마을 수동 유지·도로 자동 복귀를 실제 UI에서 확인했다. 고정된 장소 UI 관찰 중 불필요한 DOM mutation은 없었다.
- 도감에서 14회 모델 전환 후 필드로 복귀하는 실제 브라우저 시나리오 통과. 실제 GLB 요청, 애니메이션 진행, 캐시 상한과 페이지 오류 없음을 확인했다.
- 근거: `artifacts/model-profile-before.json`, `artifacts/model-streaming-after.json`, `artifacts/loading-controls-unit.log`, `artifacts/loading-controls-build.log`. 브라우저에서 `scripts/model-streaming-probe.ts`의 `inspectModelStreaming()`으로 실제 모델 검사를 재현할 수 있다.

최초 로딩에는 네트워크·GLB 파싱·텍스처 업로드가 여전히 필요하다. 접지 후보는 런타임 세 가지 동작에서 수집하며 모든 1,025종을 시각 검수한 것은 아니다. 이동 속도식과 원본 모델 파일은 바꾸지 않았다.
