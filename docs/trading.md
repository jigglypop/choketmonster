# 계정 간 포켓몬 교환과 게임 머니 거래

모험 화면 좌측 하단의 **교환**에서 초대 코드를 만들거나 상대의 코드를 입력한다. 거래에는 로그인이 필요하다. 지역 채팅과 거래 창 모두 로그인 계정 아이디를 표시한다. 코드는 두 사람이 직접 공유하며 자동으로 지역 채팅에 게시하지 않는다.

각 참가자는 박스 포켓몬 한 마리와 보낼 게임 머니를 제안할 수 있다. 포켓몬만 맞바꾸거나 한쪽은 포켓몬, 다른 쪽은 게임 머니를 보낼 수 있다. 팀에 있는 개체는 먼저 박스에 맡긴다. 배틀과 포획 선택을 끝낸 상태에서 거래를 시작하며, 거래 창이 열려 있는 동안 개인 모험을 정지하고 저장 체크포인트를 고정한다.

양쪽 계정, 포켓몬 이름·종·레벨·개체 번호, 게임 머니를 확인한 뒤 각각 확인 버튼을 누른다. 제안을 바꾸면 양쪽 확인이 취소된다. 서버는 같은 거래 버전의 확인만 처리한다. 초대와 진행 중인 거래는 마지막 변경 후 10분 뒤 만료된다.

## 저장과 개체 기억

PostgreSQL 트랜잭션 하나에서 두 계정의 현재 저장을 잠그고 제안 당시 리비전, 실제 박스 소유, 잔액과 용량을 검증한다. 어느 한쪽 저장이 바뀌었으면 확인을 다시 받아야 한다. 포켓몬과 돈은 두 저장에 함께 반영된다. 완료 요청을 다시 보내도 교환을 반복하지 않는다.

기존 개체 번호는 계정마다 `mon-1`부터 시작한다. 받은 개체에는 수신 계정의 사용하지 않은 번호를 배정하고, 이전 번호와 거래 관계는 서버 기록에 남긴다. 개체의 회로 가중치·순환 상태·난수 상태·학습 기록은 합치지 않고 이동한다. 월드 동행 기억과 보상 기록의 소유자 참조도 새 번호에 맞춘다. 다른 지역에서 가져온 동행 기억의 위치는 수신자의 안전한 위치로 맞춘다.

전체 커넥톰 기억은 기기 IndexedDB에 따로 있으므로 제안 시 별도로 내보낸다. 기록이 체크포인트 이후에 남아 있으면 `/api/local-brains/checkpoint`가 원래 계정·기기의 초기화 시드와 기록으로 정확한 현재 상태를 재구성한다. 새 행동이나 보상을 추가하지 않는다. 수신 기기는 완료된 거래의 비공개 결과에서 이를 받아 새 개체 번호로 보관한다. 기기별 거래 영수증은 재접속할 때 같은 기억으로 이후 학습을 덮어쓰지 않게 한다.

서버는 거래마다 저장의 `tradeEpoch`를 올린다. 이전 거래 시점의 백업이나 오래 열린 탭은 최신 저장 리비전만 바꿔도 옛 포켓몬·돈으로 되돌릴 수 없다. 기기 저장과 서버 결과가 충돌하면 기존 파일을 보존하고 자동 적용을 멈춘다. 이 장치는 거래와 오래된 저장의 충돌을 다룬다. 개인 모험 전체를 서버에서 판정하는 경쟁 게임 경제는 아니다.

## 통신

이동·지역 채팅은 기존 전용 실시간 EC2의 `/api/realtime`을 사용한다. 거래 변경 알림은 계정·DB API의 `/api/trades/live?profile=...` WebSocket을 사용한다. HttpOnly 세션 쿠키, 프로필 일치와 Origin을 검사하고 해당 참가자에게만 변경 알림을 보낸다. 실제 제안·확인·취소는 인증된 JSON 요청으로 처리한다. 소켓이 끊기면 상태 조회로 복구한다. 개체 기억과 저장 파일은 공개 지역 소켓에 보내지 않는다.

추가 EC2는 필요하지 않다. 기존 API와 별도 실시간 서버에 같은 실행 파일을 배포한다.

## 검증

- `scripts/verify-trade-api.ts`: 실제 PostgreSQL 두 계정의 교환, 잔액 보존, 개체 번호 충돌 처리, 기억 이동, 재확인·중복 요청과 이전 저장 차단.
- `rust-server/src/local.rs`: 실제 설치된 전체 그래프로 재구성한 체크포인트와 원본 실행의 바이트 일치, 수신 계정의 다른 개체 번호에서 이어 실행한 상태 일치.
- 관련 브라우저 시나리오: 초대 코드 참가, 제안과 확인, 소켓 알림, 완료 저장 적용, 취소와 재접속.
