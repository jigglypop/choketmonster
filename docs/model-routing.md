# Astra + Sol medium 혼합 운용

## 역할

GPT-6 Astra는 루트 에이전트이자 최종 책임자다. 사용자 의도 해석, 설계, 작업 분해, 충돌 해결, 실제 커넥톰의 출처·범위 판단, 포켓몬 자산 권리 판단, 결과 통합과 완료 판정을 맡는다.

GPT-5.6 Sol은 `reasoning_effort: medium`으로 사용한다. 공식 모델 ID는 `gpt-5.6-sol`이다. 파일과 완료 조건이 명확한 구현, 테스트 실패 원인 조사, 독립적인 데이터 변환, 문서와 코드의 불일치 점검처럼 결과를 바로 검토할 수 있는 작업을 맡는다.

## 위임할 때

다음 조건을 모두 만족할 때 Sol에 위임한다.

1. 다른 작업과 동시에 진행할 수 있다.
2. 수정 파일이나 읽기 범위를 겹치지 않게 정할 수 있다.
3. 입력, 산출물, 완료 조건과 실행 가능한 검증 명령을 한 문단으로 설명할 수 있다.
4. 위임 비용보다 절약되는 시간이 크거나 독립 검토가 실제로 유용하다.

예시는 151종 도감 데이터 생성과 검증, 실제 커넥톰 변환기 구현, UI의 도감 화면 구현, 실험 결과 감사처럼 서로 파일 경계를 나눌 수 있는 작업이다.

한두 줄 수정, 같은 코어 파일을 연속으로 고쳐야 하는 일, 방향이 아직 정해지지 않은 설계, 사용자 선택이 필요한 일은 Astra가 직접 처리한다.

## 위임 요청 형식

Sol에는 필요한 최근 맥락과 아래 항목만 전달한다.

- 목적과 수정 가능 파일
- 보존해야 할 불변조건
- 완료 조건
- 실행할 관련 검사
- 하지 말아야 할 외부 행동

Sol은 조사 결과만 설명하고 멈추지 않는다. 승인된 범위의 구현, 실행, 실패 수정, 관련 검사까지 완료한다. 사람에게 보이는 메시지는 한글 문장과 띄어쓰기를 지킨다.

## 통합 조건

Astra는 Sol의 완료 보고만 믿지 않고 변경된 파일, 실행 결과, 실패 여부를 확인한다. 두 작업이 충돌하면 사용자 최신 요청과 `AGENTS.md`의 불변조건을 기준으로 통합한다. Sol이 만든 테스트가 구현 문구를 그대로 확인하는 수준이면 제거한다.

실제 커넥톰 또는 학습 결과는 Astra가 직접 다음을 확인한 뒤 완료로 판정한다.

- 원본 정체성과 체크섬
- 변환된 회로가 정책 경로에 실제로 들어감
- 평가 중 가중치가 고정됨
- 기준 정책과 같은 환경에서 비교됨
- 리플레이가 체크포인트에서 재현됨
- 기술 통과와 생물학적 해석이 분리됨

Sol을 사용할 수 없는 실행 환경에서는 Astra가 같은 완료 조건으로 직접 수행한다. 모델 사용 여부 때문에 사용자 작업을 중단하지 않는다.

## 설정 예시

Codex 협업 도구에서 Sol 작업을 만들 때 모델은 `gpt-5.6-sol`, 추론 강도는 `medium`을 지정한다. API 하네스를 별도로 만들 경우에도 Responses API의 해당 모델과 추론 강도를 명시하고, 모델별 결과를 같은 평가 입력으로 비교한다.
