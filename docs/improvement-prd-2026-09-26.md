## 2. 포켓몬 모델 품질 전수조사

마지막 전수 감사(`artifacts/model-audit.md`)에서 모델 1,107개 중 591개가 결함으로 잡혔다. 그러나 기존 감사에는 팔 위치, 몸 기울기, 동작 전환 순간을 재는 지표가 없어 T자 자세와 비뚤어짐은 아직 수치로 잡히지 않는다. 지표를 먼저 추가하고 전 모델을 다시 잰다.

| 출처 | 개수 | 상태 |
| --- | --- | --- |
| 06wj/pokemon(1–151번, 로컬) | 151 | 모두 뼈대와 자체 동작 보유 |
| Pokemon-3D-api(152–1025번, 원격) | 820 | 뼈대+동작 110, 뼈대만 356, 노드 애니 4, 뼈대 없는 고정 모델 350 |
| HOME 추출(권리 미확인) | 54 | 뼈대만 있고 동작·텍스처 없음 |
| 폼 | 83 | 알로라 18, 메가 65 |

게임에서 동작을 얻는 방식은 자체 동작만 59, 자체+생성 216, 원본 뼈대에 생성 동작 462, 고정 모델에 뼈대까지 생성 362개다(`artifacts/model-motion-material-audit.json`). 절반 이상이 자동 생성 동작에 기대고 있다.

### T자 자세 원인

1. 서 있는 체형을 네발로 분류: 팔이 다리로 처리되고 대기 동작에서 다리 회전이 0이라 팔이 벌어진 채 남는다(`src/three/johto-rig.ts:481-482,525,549`). 해당 12종: 52, 152, 161, 172, 614, 716, 758, 827, 981, 988, 1010, 1023.
2. 고정 모델에 만든 뼈대(362개): 뼈 위치가 고정 비율이고, 머리 높이의 팔 가중치를 억제하며, 팔 내리는 각도를 실제 팔이 아닌 생성 뼈 기준으로 잰다(`src/three/johto-rig.ts:130-164,208,213,532-544`).
3. 뼈 이름: "shoulder" 뼈는 제외되고, 고릴가(810)처럼 `Bone.001` 같은 일반 이름만 있는 뼈대는 팔을 찾지 못한다. 또 "arm"이 없는 사람형 8종(401, 490, 762, 810, 881, 895, 956, 992)은 팔을 못 내린다. 8세대 보조 뼈(`tr*`)는 팔이 두 번 내려갈 수 있다(`src/three/johto-rig.ts:315-334`).
4. 동작 전환 순간: three 0.185 믹서는 나가는 동작에만 있는 뼈를 기본(T) 자세로 되돌린다. 또 믹서가 `useEffect`에서 시작돼 로드 직후 한 프레임 기본 자세가 보일 수 있다(`src/openworld/view.tsx:723-751`).

### 이동 중 비뚤어짐 원인

몸 전체는 좌우 회전만 하고 경사 맞춤이나 기울임 코드는 없다. 따라서 기울어짐은 동작 자체나 방향 문제다.

1. 걷기에 달리기 동작을 먼저 쓴다(`src/data/model-motion.ts:59`). 루트 이동은 위치만 지우고 회전은 남긴다(`src/three/johto-rig.ts:397-430`). 자체 걷기·달리기 199개 중 허리 흔들림이 10° 이상 139개, 20° 이상 93개, 45° 이상 26개다.
2. 정면 방향 오류: 감사가 37–180° 틀어졌다고 본 13개를 정면·옆·뒤에서 렌더링해 보니 12개는 눈 판정 오류였다(꼬리의 눈 무늬를 눈으로 잡은 마자용·메가야도란 등). 파오젠(1002)만 대기 클립의 허리 뼈가 약 90° 돌아가 옆을 보고, 걷기·달리기는 정면이다. 모델 전체를 돌리면 걷기가 틀어지므로 클립 단위로 고쳐야 한다.
3. 생성 걸음의 회전축이 월드 축에 고정돼 있다(`src/three/johto-rig.ts:538-541`). 방향이 틀린 모델은 다리가 옆으로 흔들리고, 걸으면서 몸이 도는 모델이 20개다(350번은 93.6°).
4. 모델 루트에 붙은 연출: 동작 없는 모델의 좌우 흔들림, 피격 흔들림, 공격 때 비균일 크기 변화(`src/openworld/view.tsx:682-686,705`).

### 전수조사 방법

1. 임시 감사 스크립트(`scripts/tmp-model-audit.ts`)를 정식 스크립트로 옮기고 JSON 결과를 남긴다.
2. 지표 5개를 추가한다: 팔 내림(생성 뼈 포함, 대기·걷기), 몸 기울기(엉덩이·척추의 좌우·앞뒤 기울기, 대기 대비), 이동 방향 대비 정면, 전환 중 기본 자세 거리, 고정 모델 팔 벌림.
3. `window.__renderProbe`(`src/openworld/render-probe.tsx`)에 포켓몬의 현재 동작·가중치, 몸 기울기, 팔 내림을 추가해 게임 안에서도 잰다. 지금은 팔 내림(`armDrop`)이 인물에만 있다.
4. 결과는 종별 표(결함 유형, 원인, 수정 방식)로 남긴다.

### 수정 방향

- 모든 동작에 대기 자세 기준의 전 뼈 키를 채워 전환 중 T자 복귀를 막는다. 믹서는 로드 즉시 시작한다.
- 걷기는 걷기 동작을 우선하고, 이동 중 허리 회전은 정해진 각도 안으로 제한한다.
- 클립마다 이동 방향 대비 정면을 재서, 파오젠처럼 한 클립만 돌아간 모델은 그 클립의 루트 회전을 맞춘다. 생성 걸음의 축은 모델 기준으로 바꾼다.
- 네발로 분류된 12종 중 실제로 서서 팔을 벌린 3종(툰베어, 염뉴트, 훔처우)만 두 발 체형으로 바꾼다. 나머지(치코리타, 제르네아스, 키키링 등)는 뿔·목 때문에 키가 커 보였을 뿐 네발이 맞다.
- 네발 체형이라도 땅에 닿지 않는 팔은 앞다리로 보지 않는다.
- 생성 뼈대의 팔 내림 각도를 뼈가 아니라 팔 메시 방향으로 잰다.
- 고정 모델 362개 중 팔 벌림이 심한 모델은 개별 보정하거나 5번의 자동 리깅 적용을 검토한다.

완료 기준: 1,107개 전부 대기·걷기에서 팔 내림·기울기·정면 기준을 통과하고, 전환 중 T자 복귀가 0건이다.

1. 메가 확장: 모델 없는 32종. 후보 출처(Cobblemon 26, navas-zamega 6, 3d-api 1)는 `artifacts/research/mega-models/missing-mega-sources.json`에 있으나 권리가 미확인이다.
2. 특성 전투 적용: 메가 특성(단단한발톱, 매직미러 등)부터. 클라이언트와 랭크 서버를 함께 고친다.
3. 체육관 관장·챔피언의 메가진화.
4. 원시회귀 2종, 가라르·히스이·팔데아 폼 40개.
5. 도감 보상, 일일 퀘스트, 업적, 이로치.

## 4. 유저 기반 기능: 채팅, 알림, 접속자 목록, 닉네임

방 단위 채팅과 주변 플레이어 표시는 이미 동작한다. 빠진 것은 닉네임, 알림함, 전체 접속자 현황, 차단·신고다. 지금은 로그인 ID(`users.username`)가 채팅·이름표·랭크 순위에 그대로 노출돼 계정 탈취 위험도 키운다.

| 기능 | 현재 | 빠진 것 | 근거 |
| --- | --- | --- | --- |
| 닉네임 | 없음. 로그인 ID를 표시 | 표시명, 중복·금칙어 검사, 변경 쿨다운 | `rust-server/src/api.rs:542-554`, `src/game/account.ts:1` |
| 채팅 | (지역, 장면) 방 단위. 1–200자, 10초에 5개, 방당 최근 50개(메모리) | 지역·전체·귓속말 채널, 금칙어, 차단·신고, 기록 보관 | `rust-server/src/realtime.rs:1025-1102`, `src/openworld/panel.ts:1049-1072` |
| 접속자 | 같은 방 목록, 48m 안 최대 12명 모델·이름표, 미니맵 점 | 지역별·전체 인원, 목록에서 교환 초대 | `src/openworld/panel.ts:1031-1047`, `src/openworld/multiplayer.ts:21-29` |
| 알림 | 5–9초 토스트 1개, 기록·뱃지 없음 | 알림함, 서버 푸시 | `src/main.ts:194-218` |
| 교환 | 12자 초대 코드를 게임 밖에서 공유 | 받는 쪽 알림(창이 열려 있을 때만 연결) | `rust-server/src/trades.rs:228-236`, `src/game/trade-panel.ts:241-257` |
| 랭크 | 패널이 열려 있을 때만 1.5–2.5초 폴링, 닫으면 30초 뒤 대기열 이탈 | 매칭·결과 푸시 | `src/game/ranked-panel.ts:71-75`, `rust-server/src/ranked.rs:596` |

### 요구사항

1. 닉네임
    - 마이그레이션 `0010`: `users.display_name`, `display_name_changed_at`, `lower(display_name)` 유니크 인덱스.
    - 규칙 초안: 2–12자 한글·영문·숫자, 앞뒤 공백 제거, 예약어·금칙어 거부.
    - `POST /api/profile/nickname`: 중복이면 409, 요청 제한, 변경 쿨다운.
    - 닉네임이 없는 계정은 로그인 직후 설정 창을 띄운다(`src/game/account-panel.ts`).
    - 채팅, 이름표, 교환, 랭크 대기열·순위의 표시를 닉네임으로 바꾼다.
    - 걸림돌: 실시간 티켓이 이름을 32바이트로 제한한다(`rust-server/src/realtime.rs:94,595`). 글자 수 기준으로 바꾼다.
2. 채팅
    - 현재 방 채널은 유지하고 지역·전체·귓속말 채널을 추가한다.
    - `normalize_chat`에 금칙어 필터를 넣는다.
    - 차단: `playerId` 기준, 클라이언트 저장. 신고: `POST /api/reports` + `reports` 테이블.
    - 채팅 금지: `users.chat_banned_until`을 티켓 발급 때 확인한다. 티켓이 40초마다 갱신되므로 40초 안에 적용된다.
    - 채팅 로그를 남겨 신고 처리 근거로 쓴다.
3. 알림
    - `/api/trades/live`를 로그인 동안 항상 연결되는 `/api/events`로 넓힌다.
    - 이벤트: 교환 초대·변경, 랭크 매칭, 랭크 결과.
    - 헤더에 뱃지가 있는 알림함을 둔다. 오프라인 보관이 필요하면 `notifications` 테이블을 추가한다.
4. 접속자 목록
    - `census` 메시지: 지역별 인원을 입장 때와 10초마다 보낸다.
    - 목록에서 교환·대전을 초대한다: `invite{to,kind,code}`를 서버가 요청 제한을 걸어 중계한다.

### 인프라 제약

- 실시간 서버는 `t3.micro` 1대, DB 없는 메모리 허브다. 서버당 128연결, 방당 64명이 상한이다.
- 배포할 때마다 소켓과 채팅 기록이 초기화된다. 여러 대로 늘리려면 Redis나 Postgres pub/sub이 필요하다.
- 같은 계정의 두 번째 탭은 409로 거부된다. API 프로세스 안에도 쓰지 않는 허브가 하나 더 떠 있다(`rust-server/src/api.rs:125`).

## 5. NPC 동작 다양화와 Tripo AI 모델링 자동화

NPC가 단조로운 이유는 세 가지다. 쓰는 모델에 대기 동작 클립이 하나도 없고, 85개 트레이너 분류가 몸 8개를 나눠 쓰며, 모든 마을의 출연진이 같다. Tripo로 모델과 동작 클립을 스크립트로 만들면 NPC 1명당 약 $0.75–1.05에 몸과 동작을 늘릴 수 있다.

### 현재 동작

- 서 있는 NPC는 손흔들기·걷기 클립의 0프레임에 멈춰 있다가 9–16초마다 손을 흔든다(`src/openworld/town-npcs.tsx:79-85,111-116`).
- 경찰은 원을 계속 돌고, 점원·체육관 안내원은 직선을 왕복한다. 움직이는 NPC는 말을 걸어도 멈추지 않는다(`src/openworld/town-npcs.tsx:104,130-144`).
- 길 트레이너는 걷기 클립 0프레임에 고정돼 몸만 돌린다. 6유닛 안에서 "!"를 띄우고 도전하지만 플레이어에게 걸어오지 않는다(`src/openworld/road-trainer-figures.tsx:32-61`).
- 체육관 관장은 3D 몸 없이 버튼만 있고(`src/openworld/gym-interior.tsx:83-94`), 포켓몬센터 안 간호사와 리그 직원도 몸이 없다.

| 모델 | 웹용 크기 | 클립 | 출처·비고 |
| --- | --- | --- | --- |
| boy, fish, glass, police2 | 1.6–3.2MB | Running, Walking, Wave_One_Hand | Tripo 출력. 원본 리그가 깨져 직접 다시 리깅 |
| nurse, docter | 4.9–6.2MB | Running, Walking, 손흔들기 1종 | 28관절 mixamo 뼈대 |
| man, mountain, teacher | 4.2–5.6MB | Running, Walking | 손흔들기 없음 |
| police | 5.0MB | Walking | 달리기·손흔들기 없음 |
| red, green | 미사용 | green에만 Idle_4(14초) | 원본 79MB가 커밋돼 있으나 쓰이지 않음 |

### NPC 요구사항

1. 모든 NPC에 대기 동작 반복을 넣고 0프레임 고정을 없앤다.
2. 대기 동작 변주(두리번거리기, 팔짱, 기다리기)를 무작위 간격으로 섞는다.
3. 플레이어가 다가오면 움직이던 NPC도 멈추고 고개를 돌려 본다.
4. 상황 반응: 배지 획득 뒤 박수, 대화 중 끄덕임, 간호사 인사.
5. 길 트레이너는 플레이어를 발견하면 걸어와서 도전한다. 패배 동작을 넣는다.
6. 체육관 관장, 센터 간호사, 리그 직원에게 몸을 준다.
7. 트레이너 분류별 몸을 늘리고 지방마다 출연진을 다르게 한다.

지상은 항상 낮이므로 시간대별 일과표는 범위에서 뺀다.

### Tripo 모델링 자동화

저장소에는 Tripo·Meshy 연동 코드가 없다. `.env`는 `.gitignore`의 `.env*`로 제외돼 있고 git 기록에도 없다. 키는 `.env`에서만 읽는다.

`scripts/generate-npc-model.ts` 하나로 다음을 실행한다.

1. 입력: 역할 ID, 프롬프트 또는 참고 이미지, 원하는 동작 목록.
2. 생성: 이미지면 업로드 후 `image_to_model`, 아니면 `text_to_model`. 모델 `v3.1-20260211`, 텍스처·PBR 켜기. 리깅할 것이므로 `export_orientation`은 비운다.
3. 리그 검사: `animate_prerigcheck`(무료)로 리깅 가능 여부 확인.
4. 리깅: `animate_rig`, `rig_type: biped`, `spec: mixamo`. 기존 모델이 `mixamorig:` 뼈대이므로 기존 걷기·달리기 클립도 재사용할 수 있다.
5. 동작: `animate_retarget`, 한 작업에 최대 5개. v1.0 리그의 `preset:biped:*` 약 99종 중 idle, walk, run, greet, wave_goodbye, bow, clap, agree, look_around, standing_relax, wait, fold_arms를 역할별로 고른다.
6. 다운로드: 결과 URL이 약 5분 뒤 만료되므로 완료 즉시 받아 `public/models/trainer/web/<역할>.glb`에 저장한다. 원본은 7번의 원본 보관 위치에 둔다.
7. 검수: GLB의 뼈대·역바인드·가중치를 검사하고, 게임에서 `?renderProbe`로 뼈 움직임과 `armDrop`을 확인한다.
8. 실패 처리: 429는 `Retry-After`만큼 기다렸다 재시도한다. 실패·취소 작업은 과금되지 않는다.

| 항목 | 크레딧 |
| --- | --- |
| 텍스처 포함 텍스트 생성 / 이미지 생성 | 20 / 30 |
| 리그 검사 / 리깅 | 0 / 25 |
| 동작 1개 | 10 |
| NPC 1명(텍스트, 동작 3개) | 75 (약 $0.75, $1 = 100크레딧) |

주의

- 기존 Tripo 출력 4개는 관절이 원점에 몰리고 가중치가 골반에만 실려 있었다(커밋 fc56851, 69ebd04). 7번 검수를 통과하지 못하면 반영하지 않는다.
- 동작 여러 개가 GLB 하나에 클립으로 담기는지는 문서로 확인되지 않는다. 첫 생성에서 확인하고, 안 되면 클립별 GLB를 합친다.
- `.env`의 기본 주소는 v2(`api.tripo3d.ai/v2/openapi`)다. 2026년 4월 나온 v3(`openapi.tripo3d.ai/v3`)도 같은 키로 쓸 수 있으므로, 요청 부분만 분리해 두고 v2로 시작한다.
- 동시 작업은 계정당 생성 10개, 동작 10개다.
- 대안으로 Meshy를 같은 스크립트의 공급자 옵션으로 둔다. Meshy는 동작 여러 개를 클립별로 합친 GLB 하나로 돌려주고, 동작 라이브러리가 680종이다.
- 루트에 값이 빈 `.env.example`을 추가한다.

완료 기준: 360×640, 390×844, 844×390, 932×430에서 가로 스크롤·가림·잘린 탭이 없고, 키보드 없이 전 기능을 쓸 수 있다.

## 7. 인물 모델 용량 정리

### 요구사항

1. 원본을 배포 경로 밖으로 옮긴다: `public/models/trainer/*.glb` 12개를 `assets/trainer-source/`로 옮기고 `.gitignore`에 넣는다. 삭제하지 않고 옮기기만 하므로 원본은 그대로 남는다.
2. 커밋된 원본 4개(161.3MB)는 추적에서 뺀다. 과거 기록에 남은 용량까지 줄이려면 기록 재작성이 필요하므로 별도로 결정한다.
3. 배포 검사: `scripts/prepare-deploy.ts`가 `models/trainer/*.glb`(웹용 제외)를 거부하도록 제외 규칙을 넓힌다.
4. 웹용 경량화, 해상도는 유지한다.
    - 기하·동작 데이터에 meshopt 압축을 적용한다. three의 `MeshoptDecoder`를 로더에 연결한다.
    - 법선 맵을 무손실에서 고품질 손실 WebP로 바꾸는 안은 원본과 나란히 비교한 뒤 승인받아 진행한다.
    - KTX2 변환은 GPU 메모리까지 줄지만 화질 비교가 필요해 같은 조건으로 둔다.
5. 경량화 변환을 스크립트로 남긴다(`scripts/optimize-figures.ts`). 지금은 웹용 복사본을 손으로 만들어 재현할 수 없다. 5번 섹션의 Tripo 스크립트도 같은 변환을 거친다.
6. 쓰지 않는 red·green은 원본 보관 위치로만 옮기고, 쓸지 여부는 따로 정한다(green에는 유일한 대기 동작 Idle_4가 있다).

완료 기준: 배포물에 원본 인물 모델 0개, `public/models/trainer/`는 웹용 10개만 남음, 게임 안에서 텍스처·뼈 움직임·T자 여부를 `?renderProbe`로 확인.

적용 결과(2026-09-26): 원본 12개를 `assets/trainer-source/`로 옮겼고, 웹용 10개는 40.7MB에서 18MB로 줄였다. 변환은 `scripts/optimize-figures.ts`로 한다. 거칠기·금속 맵은 게임이 쓰지 않아 뺐고, 법선 맵은 1024px 무손실로, 모양·동작은 meshopt로 압축했다. 색상 맵은 2048px 그대로다. 원본과 나란히 렌더링해 차이가 없음을 확인했다. 변환 원본은 `assets/trainer-source/web/`에 있다.
