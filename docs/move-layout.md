# 기술 배치와 자동 공격

공격 기술은 물리·특수 분류를 기준으로 표시 목록 앞에 놓는다. 사용자는 월드의 기술 배치 버튼이나 팀·박스 상세의 ▲▼로 같은 분류 안의 순서를 바꾼다. 월드 버튼·숫자 1~4와 일반 배틀 화면도 이 순서를 사용한다. 전투 중 편집은 막는다.

`Monster.moveOrder`에는 기술 ID 선호 순서만 저장한다. 실제 `moves` 배열과 신경 입력·출력의 슬롯 번호, 각 기술 PP, 개체별 회로 상태는 재배치하지 않는다. `getMoveLayout`이 표시 위치를 원래 슬롯 번호로 연결한다. 따라서 배치 변경이 다른 기술의 PP를 소비하거나 기존 학습 기록을 다른 기술에 붙이지 않는다. 레벨업과 진화에서는 남은 기술의 순서를 유지하고 새 기술을 추가한다. IndexedDB·내보내기·서버 저장에서 같은 선택을 보존한다. TypeScript와 Rust는 배치가 현재 기술의 중복 없는 ID 목록인지 검증한다.

기존 자동 습득은 습득 레벨순 마지막 네 기술만 골랐으므로 공격을 배운 종도 변화 기술 네 개만 가질 수 있었다. 생성·자동 습득은 이제 실제 엔진에서 피해를 줄 수 있는 공격을 최소 하나 보존한다. 이전 저장은 임의 교체하지 않는다. 공격을 배운 적이 있지만 현재 없다면, 상세 화면에서 해당 종이 현재 레벨까지 배우는 공격 중 하나를 직접 고를 수 있다. 네 칸이 차면 화면의 첫 변화 기술을 교체하고, 원래 상태를 IndexedDB에 백업한다. 다른 기술의 PP와 뇌 가중치는 유지하며 지난 선택의 임시 보상 연결만 끊는다. 이미 공격을 보유한 경우에는 다시 복구할 수 없어 이 동작을 반복해 공격 PP를 채울 수 없다.

자동 배틀은 상대에게 면역되지 않고 PP가 남은 유효 공격 중에서 매 턴 선택한다. 공격이 없으면 사용 가능한 변화 기술을 선택하고, 모든 PP가 없으면 엔진의 발버둥을 사용한다. 공격 명령을 선택하더라도 빗나감·잠듦·마비 같은 배틀 규칙 때문에 피해가 없을 수 있다. 이 공격 우선순위는 게임 제어 규칙이며 학습 향상이나 생물학적 지능을 뜻하지 않는다. 제한된 정책 비교와 리플레이 근거는 [실험 문서](experiments.md)에 기록했다.
