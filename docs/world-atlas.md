# 월드 아틀라스 설계

`src/openworld/atlas.ts`는 관동, 성도, 호연, 신오, 하나, 칼로스, 알로라, 가라르, 히스이, 팔데아를 같은 런타임 인터페이스로 제공한다. 관동은 기존 `kanto.ts`의 위치, 관문, 체육관, 충돌, 이동 판정을 그대로 위임한다. 나머지 아홉 지역은 대표 거점과 지역 특징을 약 `-120..120` 좌표에 다시 배치한 초켓몬스터 전용 압축 탐험 지도다.

이 좌표와 도로 형상은 원작 게임의 맵 데이터나 타일을 복제한 것이 아니다. 공식 지역명과 대표 장소의 정체성만 참고했고, 거리, 방향, 축척, 지형 높이, 건물 배치, 연결 순서는 이 프로젝트의 이동성과 작은 월드 렌더링을 위해 직접 설계했다. 화면에는 게임용으로 재구성한 탐험 지도임을 표시한다. 저장에는 지역별 `*-atlas-v1` 버전을 기록한다.

각 새 지도는 다음 공통 규칙을 사용한다.

- 대표 거점 사이에 고유 ID의 연결로를 넣고, 선언된 모든 `surfaceConnections` 중심선을 보행 가능하게 만든다.
- 마을 중심은 안전 도착 지점으로 비우고, 관동에서 사용하는 건물 오프셋 배치 규칙을 재사용해 주변 건물 충돌을 만든다.
- 높이는 연속 사인 곡면과 지역별 지형 오프셋으로 계산한다. 연결로 안에서는 급격한 높이 단절이 없다.
- 도로 밖은 숲, 호수, 암반 같은 막힌 지형이다. 성도의 분노의호수와 방울탑, 호연의 굴뚝산과 해안, 신오의 천관산, 알로라의 섬 사이 바다처럼 각 지역의 인상을 작은 지형 구역으로 표현한다.
- 각 위치의 대표 서식 종을 명시하고, 선택 버전의 전체 도감도 타입·서식지 기준으로 분산 배치한다. 대표 목록에 없는 진화형과 특수 진화 종도 포획할 수 있다. 이는 본가의 야생 출현표가 아닌 게임 규칙이다.
- 새 지역은 우선 자유 탐험용이므로 `gates`와 `gyms`가 비어 있다. 이후 진행 시스템을 붙일 때 같은 인터페이스로 추가할 수 있다.

버전 매핑은 생성 데이터의 53개 ID를 모두 다룬다. `colosseum`과 `xd`는 현재 지역 ID 집합에 오레가 없어 호연 탐험 지도를 사용한다. `champions`는 관동을 기본 진입점으로 사용한다. `legends-za`와 `mega-dimension`은 칼로스, `legends-arceus`는 히스이로 연결한다.

장소 및 지역 표기의 기준은 Pokémon 공식 자료다. Pokémon Company의 [Pokémon Evolutions 공식 보도 자료](https://press.pokemon.com/en/Pokemon-Evolutions/Focus/Pokemon-Evolutions-videos)는 관동부터 가라르까지 주요 지역 계보를 확인하는 데 사용했다. [Pokémon Legends: Arceus 공식 스토리](https://legends.arceus.pokemon.com/en-us/story/)는 히스이와 축복마을(Jubilife Village), [Pokémon 공식 부모 안내](https://parents.pokemon.com/en-us/video-games-and-apps/)는 팔데아 지역 설명, [가라르 공식 관광 안내서](https://assets.pokemon.com/assets/cms2/pdf/video-game/sword-shield/Galar_Tour_Brochure_US.pdf)는 가라르 표기를 확인하는 데 사용했다. 세부 한국어 장소명은 저장소의 한국어 포켓몬 데이터 표기 관례에 맞췄다.

`tests/world-atlas.test.ts`는 관동 위임 동일성, 10개 지역 ID, 53개 버전 매핑, 연결 그래프의 보행 가능성, 높이 연속성, 건물 충돌, 안전 도착, 서식 종 범위와 저장된 지역 ID 복원을 검사한다.

## 지역 이동과 저장

지역 지도 선택창이나 수집 버전을 바꾸면 해당 지역 시작 마을로 이동한다. 전국도감은 현재 지역을 유지한다. 포획 기록·소유 개체·개체별 회로 기억은 유지하고 야생 배치와 이동 목적지는 새로 만든다. 전투·포획 중에는 지역 이동을 막는다. 방문 마을은 지역별로 저장한다. 지역 정보가 없던 기존 저장은 버전 선택에 관계없이 관동으로 복원한다. 서버도 알려진 지역·지도 버전 조합을 검증한다.

이동 속도는 기존 능력치 계산 결과의 2.2배, 상한 초당 11월드 단위다. 전투·몬스터볼 보충·신경 계산 시간은 가속하지 않는다.

## 화면과 거리 기준 LOD

- 지형을 40×40 단위의 36개 구역으로 나눈다. 플레이어 주변과 카메라에 보이는 구역만 만들고, 가까운 구역은 12분할·먼 구역은 4분할 메시를 사용한다. 서로 다른 해상도의 경계에는 수직 연결 면을 둔다.
- 포켓몬은 거리와 카메라 시야로 거른 뒤 데스크톱 최대 8개·모바일 최대 4개를 3D로 표시한다. 3D 반경은 각각 32·22 단위이며, 중거리는 해당 종의 스프라이트, 가시 반경 밖은 표시하지 않는다. 화면에 남는 개체 전체도 각각 16·10개로 제한한다.
- GLB 요청은 동시에 최대 3개, Draco 디코딩 작업자는 최대 2개다. 아직 시작하지 않은 요청이 시야에서 빠지면 취소한다. 이미 시작한 전송은 완료 후 캐시에서 관리한다. 실패 모델은 60초 재시도 간격을 두고 이미지로 대체한다.
- 참조가 없는 모델부터 LRU로 정리하며 캐시 목표는 16개다. 현재 표시 중인 자연 소품·포켓몬 때문에 이 수를 넘을 수 있다. 자연 소품도 가까운 시야에 배치가 있을 때만 원본 모델을 요청한다.
- 각 지역은 서로 다른 마을·길·지형 색과 코드로 만든 지역 상징물을 사용한다. 전 지역의 메시나 전체 포켓몬 모델을 미리 다운로드하지 않는다.
- 새 원본 모델에 애니메이션 클립이 없으면 이동에 맞춘 작은 기울기·상하 움직임을 게임 코드에서 적용한다. 이는 원본의 골격 걷기 애니메이션이 아니다.

`tests/world-lod.test.ts`는 시야 밖·먼 개체 제외, 기기별 3D 예산, 중거리 이미지 전환, 지형 범위와 해상도를 검사한다. `tests/world-regions.test.ts`는 지도 전환·버전 연결·저장 복원·기억 보존·기존 저장 호환·이동을 확인한다. 실제 브라우저 검사는 `tests/ui/world-regions.spec.ts`에서 추가 세대 Draco 모델 표시, 이동, 지역 변경 후 새로고침, 모바일 예산을 확인하며 `artifacts/world-expansion`에 화면과 렌더링 관측 결과를 남긴다.

2026-09-13 로컬 검증: Vitest 27개 파일·140개 검사, Rust 11개 검사, 지역·수집·모바일·저장 브라우저 4개 시나리오와 프로덕션 빌드가 통과했다. 성도 시작 화면에서 치코리타·리아코·해루미의 실제 모델이 표시됐고, 36개 지형 중 8개 생성·동시 모델 요청 3개를 관측했다. 모바일 3D 예산은 4개였다. 자동화 브라우저는 SwiftShader 소프트웨어 렌더러이므로 이 결과를 실제 휴대폰의 프레임 성능 측정으로 해석하지 않는다.
