# GPT-6 Astra + GPT-5.6 Sol medium 하네스 정비 기록

정비일: 2026-09-10

참고한 [PyTorchKR 정리 글](https://discuss.pytorch.kr/t/openai-gpt-6-astra/11846)과 [OpenAI 공식 모델 가이드](https://developers.openai.com/api/docs/guides/latest-model)의 공통 요지는 다음과 같다. Astra는 긴 지시를 잘 따르므로 오래된 지시의 충돌이 더 큰 영향을 준다. 안전한 작업은 계속 진행하도록 권한을 분명히 하고, 결과가 큰 행동의 승인 시점을 마지막으로 옮긴다. 검증은 변경 규모에 맞추고 이미 통과한 검사를 이유 없이 반복하지 않는다.

혼합 운용의 보조 모델은 `gpt-5.6-sol`, 추론 강도는 `medium`으로 고정했다. OpenAI Docs에서 Sol은 복잡한 전문 작업용 모델이며 `medium`이 기본 추론 강도로 지원된다. 작업 분해와 최종 판단은 Astra가 유지하고, 결과 계약이 분명한 실행 작업만 Sol에 맡긴다.

## 감사 결과

기존 `AGENTS.md`에는 “생물학적 커넥톰은 나중 단계”라는 고정된 목표가 있었다. 이는 실제 커넥톰 연결을 요청한 최신 목표와 충돌했다. 512노드·5만 엣지·60초 제한도 현재 CSV 부분 회로 도구의 보호 한도인데, 프로젝트 전체의 연구 범위처럼 적혀 있었다. 두 문구를 전역 작업 제한에서 제거하고 실제 가져오기 도구의 문서에만 남겼다.

기존 스킬은 영어였고 “현재 합성 벤치마크”를 기본 경로로 강조해 실제 연결 요청에서도 합성 단계에 머물 여지가 있었다. 스킬을 한국어로 줄이고 실제 데이터 작업의 결과 조건만 유지했다. 단순 UI 작업에는 스킬을 사용하지 않도록 호출 조건도 좁혔다.

## 현재 구조

`AGENTS.md`에는 제품 목표, 실행 권한, 실제 데이터의 정체성, 완료 조건만 둔다. 세부 보상 수치와 명령은 작업할 때만 여는 `docs/experiments.md`와 `docs/connectome.md`에 둔다. 스킬은 두 문서로 가는 짧은 진입점이다.

모델 라우팅의 세부 기준은 `docs/model-routing.md`로 분리했다. 평소에는 읽지 않고 병렬 위임이 실제 후보일 때만 연다.

검증 명령은 목적별로 나눴다.

| 명령 | 사용 시점 |
|---|---|
| `npm run build` | 문구·스타일·구성처럼 빌드 영향만 확인할 때 |
| `npm test` | 코어 시뮬레이션·데이터 변환을 바꿨을 때 |
| `npm run check` | 코어 변경의 단위 테스트와 빌드를 함께 확인할 때 |
| `npm run check:ui -- --grep "시나리오"` | 사용자 흐름을 바꿨을 때 관련 Playwright 시나리오만 확인할 때 |
| `npm run check:full` | 여러 층을 크게 바꿨거나 출시 후보를 검사할 때 |

학습·회로 변경에는 위 검사와 별도로 제한된 비교 실험과 리플레이 검증이 필요하다. 이전 실험 폴더는 덮어쓰지 않는다.

## 작업 요청에 넣을 완료 조건

구현을 요청할 때 “코드를 작성해 줘”에서 끝내지 않고 다음 결과를 요구한다.

> 요청한 기능을 구현하고 실제로 실행해 결과를 확인하라. 발견한 실패는 범위 안에서 수정하고 관련 검사만 다시 실행하라. 기술 검사와 제품 결과를 구분해 보고하라. 유료 작업·계정 접근·외부 게시 직전에는 지금까지의 결과를 검토 가능한 상태로 만든 뒤 승인을 요청하라.

실제 커넥톰 작업에는 다음 문장을 추가한다.

> 원본 URL·버전·라이선스·SHA-256·선택 범위·변환 가정을 기록하고, 변환된 회로가 게임 행동 계산에 실제로 쓰였다는 리플레이를 남겨라. 결과가 나쁘더라도 그대로 보고하라.

## 유지 원칙

새 실패 하나를 모든 작업에 적용되는 규칙으로 즉시 추가하지 않는다. 같은 실패가 반복되거나 결과의 정체성·재현성·권한 경계를 해칠 때만 좁은 지침이나 검사로 보완한다. 세부 절차는 해당 작업 문서에 두고, `AGENTS.md`와 스킬에는 여러 작업에서 계속 필요한 판단 기준만 남긴다.
